## TL;DR

- RustWeek 2026 にて、Linux メンテナの重鎮 Greg Kroah-Hartman (Greg-KH) 氏が「Rust は Linux を救う」と宣言。
- メモリ安全性の導入により、カーネルにおける CVE の 70〜80% を根本的に排除できるとの見通し。
- 新しい静的解析ツール **KLint** が発表。カーネル固有の制約（スピンロック保持中のスリープ禁止など）を Rust の型システムと連携して検証。
- 「既存の C コードをすべて書き換える」のではなく、インターオペラビリティ（相互運用性）を重視した現実的な進化へ。

## 背景

Linux カーネルへの Rust 導入が始まってから数年が経過しましたが、2026年5月にオランダで開催された「RustWeek 2026」において、一つの大きな転換点を迎える発言がありました。Linux カーネルの安定版メンテナとして知られる Greg Kroah-Hartman 氏が、「Rust is going to save Linux」という非常に強いメッセージを発信したのです。

長年 C 言語で構築されてきた巨大なエコシステムにおいて、なぜ今、Rust が「救世主」として扱われるのか。それは単なるプログラミング言語の好みの問題ではなく、OS カーネルが直面している「脆弱性の質」と「メンテナンスの限界」に対する、極めて実務的な回答といえます。

## 「Rust は Linux を救う」の真意：CVE の 70-80% を撲滅する

Greg-KH 氏が強調したのは、Rust のメモリ安全性による脆弱性の削減効果です。カーネルにおける脆弱性（CVE）の多くは、Use-after-free や Out-of-bounds アクセスといった、C 言語特有のメモリ管理ミスに起因しています。

Rust を導入することで、これらのミスはコンパイル時に捕捉可能になります。Greg-KH 氏によれば、これによりカーネルで報告される CVE の 70〜80% を理論的に排除できるといいます。これは、セキュリティパッチの対応に追われるメンテナの負担を劇的に軽減するだけでなく、Linux というインフラ全体の信頼性を底上げすることを意味します。

また、同氏は「Rust はプログラミングを再び楽しくしてくれる」とも述べています。コンパイラがメモリ安全性を保証してくれるおかげで、開発者は「壊すこと」を恐れずに、ロジックの実装に集中できる。この心理的安全性こそが、次世代のカーネル開発者を惹きつける鍵となるのです。

## 技術詳解：カーネル固有ルールの番人「KLint」

Rust の標準的なチェックだけでは、カーネル開発におけるすべての罠を防ぐことはできません。そこで発表されたのが、Gary Guo 氏によって開発されている **KLint** です。

KLint は、`rustc` のドライバとして動作する静的解析ツールで、カーネル固有のプログラミングルールを検証します。その代表的な機能が **Atomic context checking** です。

### スピンロック保持中のスリープを許さない

Linux カーネルには、「スピンロックを保持している最中や、割り込みハンドラの中（アトミックコンテキスト）で、スリープする可能性のある関数を呼んではいけない」という厳格なルールがあります。これに違反すると、システムは容易にデッドロックに陥ります。

KLint は、Rust の型システムやアトリビュートを利用して、関数が「スリープ可能（may sleep）」か「アトミックコンテキストで安全か」を追跡します。

```rust
// KLint による解析のイメージ
#[klint::preemptible]
fn might_sleep() {
    // ... スリープする可能性のある処理 ...
}

fn kernel_code() {
    let _guard = spinlock.lock();
    // ここで might_sleep() を呼ぶと、KLint がコンパイルエラーを出す
    might_sleep(); 
}
```

このように、C 言語では熟練の勘とランタイムのデバッグツール（`DEBUG_ATOMIC_SLEEP` など）に頼っていた検証を、KLint はコンパイル段階で静的に行います。これは、Rust-for-Linux プロジェクトが単に言語を Rust に変えるだけでなく、カーネル開発のツールチェーンそのものを進化させている証左といえます。

## 考察：インターオペラビリティが拓く現実的な進化

今回の発表を通じて改めて感じたのは、Rust-for-Linux が掲げる「Interop is the new rewrite（相互運用こそが新しい書き換えである）」という戦略の正しさです。

数千万行に及ぶ C 言語の資産をすべて Rust で書き換えるのは現実的ではありません。しかし、新しいドライバやサブシステムを Rust で書き、KLint のようなツールで安全性を担保しながら C コードと共存させる。この「漸進的な移行」こそが、Linux という巨大なプロジェクトが死文化せずに生き残るための唯一の道でしょう。

筆者が開発している BGP Sentinel のようなネットワークスタックにおいても、Rust による安全性と C との相互運用性は非常に重要なテーマです。カーネル内部での Rust 活用が進むことで、より堅牢なネットワーク基盤を構築するための知見が共有されることを期待しています。

## まとめ

Greg Kroah-Hartman 氏の「Rust は Linux を救う」という言葉は、決して大げさな宣伝ではありません。メモリ安全性による脆弱性の劇的な削減、そして KLint のようなカーネル特化型ツールの登場により、Linux カーネル開発はより「安全」で「楽しい」ステージへと移行しようとしています。

既存の C 言語メンテナとの文化的な摩擦や、学習コストといった課題は依然として存在しますが、技術的なメリットはもはや無視できないレベルに達しています。Linux の未来は、Rust という新しい血液によって、より強固なものへと再構築されていくことになるでしょう。
