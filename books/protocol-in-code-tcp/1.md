## TCPは「暗記するもの」になっていないか

TCPを勉強したことがある人は多いはずです。3ウェイハンドシェイク、シーケンス番号、ウィンドウ、輻輳制御、TIME_WAIT ―― 用語は言えるし、状態遷移図も見たことがある。それでもいざ「なぜハンドシェイクはパケット2つでも4つでもなく3つなのか」「ウィンドウって結局どこに保存されている数字なのか」と訊かれると、言葉に詰まる。

原因は、TCPを**仕様の暗記対象**として学んだからです。RFC 9293 は正確ですが、正確さは理解ではありません。図は状態の名前を教えてくれますが、その状態が**何のデータで、どのコードによって切り替わるのか**は教えてくれません。

この本の立場は一つだけです ―― **TCPは、読めるコードである**。

## この本がやること

標準ライブラリだけで書いた、小さくて動く TCP 実装を用意しました。ソケットも、OSカーネルも、バイト列の送受信も出てきません。出てくるのは、TCPが**何を判断しているか**だけを抜き出した Python のデータクラスと関数です。

各章はソースファイル1つに対応します。全11本のファイルを、次の順で読みます。

| 部 | 章 | 読むもの |
|---|---|---|
| 第I部 **型と状態** | 1〜3 | セグメントとは何か / ハンドシェイク / シーケンス番号の一周 |
| 第II部 **流量と時間** | 4〜7 | ウィンドウ / 再送タイマー / 高速再送 / 輻輳ウィンドウ |
| 第III部 **順序と終わり** | 8〜11 | 順序の乱れの吸収 / teardown / RST / 全部を繋いだループ |

第I部で「TCPが扱う語彙（型）」を作り、第II部で「失うことと制御すること」を、第III部で「並べ直しと、会話の終わらせ方」を読みます。最後の第11章で、それまで別々に読んだ部品が1つのオブジェクトに配線され、TCPエンドポイント1つの一生として動きます。

## 読み方 ―― コードとして読む

各章は同じ4ステップで進みます。

1. **元コードを読む** ―― その章のソースファイルを、関数の呼ばれる順に追う
2. **判断の流れを掴む** ―― コードが「どの条件で何を返すか」を図にして確認する
3. **自分で答える問い** ―― コードを見れば答えられる質問に、docstring ではなく**関数の本体**で答える
4. **動かして確認する** ―― walkthrough スクリプトを実行し、`[OK]`/`[NG]` で予想と突き合わせる

コードは全部この本に載っているので、手元に環境がなくても読めます。ただ、実際に動かせるなら動かしたほうが速く腑に落ちます。実行はどの章も同じ形です。

```bash
PYTHONPATH=src python3 examples/tcp/session_01_walkthrough.py
```

## この本を貫くテーマ ―― 「同じ形」が何度も出てくる

読み進めると気づくはずです。TCPの別々に見える仕組みが、**同じコード構造**を繰り返し使っていることに。

- 「期限つきの値」―― 再送タイマーも、TIME_WAIT の待ち時間も、同じ「時刻を持って、時が来たら切り替わる」形をしている
- 「沈黙は障害の合図」―― パケットが**来ない**ことを、来たパケットから推測する。高速再送も、タイムアウトも、これをやっている
- 「その数字は保存されていない、計算されている」―― ウィンドウも輻輳ウィンドウも、状態としてどこかに書いてあるのではなく、その瞬間に**求める**数字だ

これらが繰り返し出てくることに気づけると、TCPは「暗記すべき10個の別々の仕組み」から「少数のアイデアの組み合わせ」に変わります。それがこの本のゴールです。

## おもちゃであることの正直な断り

この実装は教材用の「おもちゃ」です。実物のTCPが持つチェックサム、オプション（MSS、ウィンドウスケーリング、SACK、タイムスタンプ）、URGポインタ周りの配線は、意図的に削ってあります。残したのは、**コースの他の部分が実際に推論に使うフィールドと判断だけ**です。

これは手抜きではなく設計です。実物の複雑さを全部載せると、肝心の「TCPが何を判断しているか」が埋もれます。削ることで、判断そのものが読めるようになります。どこを削ったかは各章で明示するので、実物との差分もちゃんと分かるようになっています。

では、第1章から始めましょう。TCPの一番小さな単位 ―― セグメント ―― が、実は何を運んでいるのかを読みます。
